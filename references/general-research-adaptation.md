# 从 PPT 到任意研究领域：对应式延伸

课件的骨架是“视野 → 选题 → 方法 → 实验迭代 → 写作”，案例来自 3D 重建。换领域时保留骨架，替换名词和证据形态。

每条适配都要显式写一句：

> 这里把课件的【X】对应为【Y】，因为【理由】；课件原意不变。

没有这句话，读者会分不清哪些是课件原句、哪些是技能延伸。

---

## 1. 先填领域事实表

在给任何建议前，先让用户填（或从材料中提取）这张表。缺失项写 `[待确认]`。

| 字段 | 要问的问题 | 例子（生物） | 例子（材料） |
|---|---|---|---|
| 研究对象 | 你到底研究什么系统/现象/人群？ | 某类细胞在缺氧下的代谢重编程 | 某类钙钛矿薄膜的离子迁移 |
| 任务 | 要预测、解释、优化还是控制？ | 解释机制并预测干预效果 | 优化组分与退火工艺 |
| 输入 | 你能控制或观测的自变量是什么？ | 基因表达、氧浓度、时间点 | 组分比例、温度、时间 |
| 输出 | 你要的因变量/产物是什么？ | 代谢通量、存活率 | 转换效率、稳定性 |
| 约束 | 样本量、伦理、设备、成本、时间？ | 原代细胞数量有限 | 表征机时有限 |
| 评价指标 | 什么算“更好”？ | 预测误差、机制可检验性 | PCE、T80 寿命 |
| 当前基线 | 领域内标准做法是什么？ | 某常用通路模型 | 某标准配方 |
| 已知 failure case | 基线在哪里明显失效？ | 某类样本上预测崩 | 高湿条件下衰减 |
| 用户阶段 | junior / senior？ | junior | senior |
| 资源上限 | 算力、经费、周期？ | 单细胞平台排队 2 个月 | 每周 2 次镀膜 |

这张表就是 P12 的 setting 具体化。填不出来，说明还没到选题。

## 2. 阶段映射

### 2.1 建立领域视野

课件做法：milestone papers → 前后论文 → 问题/pipeline/技术见解 → 技术演变 + 热点演变。

跨领域替换：

| 课件 | 可替换为 |
|---|---|
| milestone paper | 标志性方法、标准方案、关键数据集、理论突破、经典实验 |
| pipeline | 实验流程、证明链、数据处理链、临床路径、工艺路线 |
| technical insight | 机制解释、设计原则、适用边界、失效条件 |
| 引用次数排序 | 综述共识、指南推荐、专家共识、复现次数；没有可靠依据时不要假装有 |
| Connected Papers | 综述的引文网络、数据库的 cited-by、导师/同行的推荐 |

输出仍然是时间轴 + 四问：终极目标、当前水平、未解问题、当前热点。

**没有文献数据时**：不要编引用次数和年份。写“待检索”，并给出可执行的检索式（数据库、关键词、时间范围、筛选标准）。

### 2.2 课题初始化

课件三标准：发展空间大且竞争小、难度与能力匹配、影响大；四步：视野 → 重要问题 → 评估竞争/空间/能力 → Aim High。

跨领域时保留这些判断维度，但把“竞争”换成领域内可观察的指标：

- 近三年同一问题有多少团队在做？
- 是否已有标准方案足够好？
- 数据/样本/设备是否被少数团队垄断？
- 你的独特资源是什么（队列、平台、临床 access、算力、工艺）？

**不要**把“竞争小”理解成“没人做所以随便做”；课件同时要求“重要问题”和“影响大”。

### 2.3 方法设计

课件四步：第一性原理分析 SOTA 为何不足 → 设计方法 → 判断合理性 → 读论文/讨论/实验改进。

跨领域对应：

| 研究类型 | “pipeline 改动”对应 |
|---|---|
| 实验科学 | 新的实验设计、干预方案、测量流程、对照设置 |
| 理论/数学 | 新的假设、引理链、证明策略、反例构造 |
| 计算/工程 | 新算法、新系统、新数据处理链 |
| 临床/公卫 | 新诊断路径、分层规则、干预流程 |
| 社科 | 新识别策略、测量工具、数据链接方式、机制模型 |

仍然要求三要点：

1. 不止 work，要有概念上的新东西；
2. 改动尽量在“机制层”，不是只调参数；
3. 能说清产生了什么新知识、新认识或新观点。

### 2.4 实验迭代

课件：拆 pipeline、拆 setting、排 exploration points；初始 idea 常不 work；SGD 式“误差→梯度→改进”。

跨领域对应：

| 课件 | 实验科学 | 理论 | 计算 |
|---|---|---|---|
| exploration point | 一个待验证的机制假设 | 一个待证明的引理 | 一个待消融的模块 |
| 拆 pipeline | 分阶段实验：先体外再体内 | 先证特例再证一般 | 先 toy 数据再真实数据 |
| 拆 setting | 先标准条件再极端条件 | 先弱假设再强假设 | 先小规模再大规模 |
| comparison | 与标准方案/阳性对照比 | 与已有定理/界比 | 与 baseline 算法比 |
| ablation | 单因素去掉某处理 | 去掉某假设看结论是否还成立 | 去掉某组件看指标 |
| gradient | 误差来源分析 | 证明卡点分析 | 错误分析/失败样本分析 |

输出物：一张 exploration points 表，每行有“假设、实验、判据、优先级、如果失败说明什么”。

### 2.5 论文写作

课件 story：任务 → 旧方法/挑战 → 贡献 → 技术优势/insight → 证据。

跨领域保留五段，但“技术优势”可换成：

- 实验科学：机制上的可解释性、可重复性、适用边界；
- 理论：假设更弱、结论更强、证明更短；
- 临床：可操作性、分层收益、风险可控；
- 社科：识别更干净、外部效度、机制证据。

Method 写法仍然有效：每个小节先“输入 → 步骤 → 输出”，再“为什么这样做 → 相比标准做法好在哪”。

## 3. 适配的自检

输出前问自己：

1. 我是否保留了课件的判断维度，而不是换成另一套价值观？
2. 我是否标注了每个映射的理由？
3. 我是否把“课件原句”和“我的延伸”分开？
4. 我是否把领域事实留白，而不是替用户编？
5. 用户能否拿这张表去执行，而不是只读一段解释？

五问有一项答不上来，就重写。
