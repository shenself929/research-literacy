# 质量、证据与边界

本文件是 `research-literacy` 交付前的自检清单。

---

## 1. 来源标签

| 标签 | 含义 | 使用场景 |
|---|---|---|
| `[PPT原文]` | 课件明确写出的流程、判断、公式、案例 | 引用方法论、页码、案例时 |
| `[用户信息]` | 用户提供的领域、baseline、结果、时间、资源 | 做诊断和个性化建议时 |
| `[外部证据]` | 用户给的论文、代码、日志、数据 | 需要指回具体节/图/表/行时 |
| `[推测/待确认]` | 合理推断但无证据 | 只能作为假设，不能当结论 |

规则：

- 同一个回答里混用多种来源时，逐条标注，不要只在开头写一次。
- `[推测]` 不能升级成 `[PPT原文]`；用户确认后才能升级为 `[用户信息]`。
- 外部证据要写位置：`论文 §3.2 / Fig. 4 / Table 2`，或 `代码 file.py:120`。

---

## 2. 证据优先级

```text
用户自己的实验/数据/日志
> 用户提供的论文原文/代码
> 课件原文
> 二手总结/博客/记忆
```

冲突时不要静默选择，写成：

```text
[PPT原文] 说……
[外部证据] 显示……
本回答采用……，因为……
```

课件与用户领域冲突时，课件是方法论来源，用户领域事实优先；不要把课件案例硬套到用户领域。

---

## 3. 不能承诺的事

课件 P5 明确：课程能教流程、规则、经验；不能替代实践培养以下能力：

- 想 Idea 的能力（创新能力、技术能力）；
- 做实验的能力（编程、分析、技术经验、沟通）；
- 论文写作能力（表达、英语、艺术、时间规划）。

因此：

- 不说“按这个流程做就一定能发论文/拿奖/申到项目”；
- 不把“填完模板”等同于“有了创新点”；
- 不替用户判断“这个题一定有价值”，只给判断维度和待验证项；
- 不承诺替用户读完全部文献或写完论文。

---

## 4. 作业口径

正式作业只有一个（P66）：

> 自己研究方向的时间轴思维导图 + 当前未解决的重要问题，PDF 提交。

以下都不是正式作业，不能混写：

- 按解析树读论文；
- 跑 baseline、设小改进；
- 在新 setting 跑 SOTA 找 failure case；
- 列 techniques 脑图、组合 pipeline；
- 做 demo/application；
- 完成论文投稿。

用户说“作业”时，先确认指的是 P66 正式作业还是课程过程性任务；不要默认把 Project 计划当成作业交。

## 5. 不编造清单

交付前逐项检查：

- [ ] 没有虚构论文标题、作者、年份、期刊；
- [ ] 没有虚构引用次数、影响因子、SOTA 数值；
- [ ] 没有虚构实验结果、消融数字、数据集规模；
- [ ] 没有虚构截止日期、审稿周期、会议时间；
- [ ] 没有把“常见做法”写成“某论文证明”；
- [ ] 没有把 4K4D/Neural Body 的案例数字当成用户领域的事实；
- [ ] 没有把课件的“6 月 31 日”静默改成有效日期。

缺证据时写：

```text
[待检索] 需要查：<数据库/关键词/时间范围>
[待验证] 需要做：<最小实验/对照/复现>
[待确认] 需要用户提供：<字段>
```

## 6. PDF 来源说明

- 课件正文来自课程整理稿 `week_1_notes.html`；该整理稿自称整理自 `week_1.pdf` 全部 81 页。整理稿与原始 PDF 未随本技能分发。
- `week_1.pdf` 当前受密码保护，未能独立读取文本、图像或页数。
- 因此：
  - `Pxx` 一律写作“HTML 记录的课件页码”；
  - 不写“已核对 PDF 第 xx 页”；
  - 不尝试破解、去除密码或修改原 PDF；
  - 如用户提供无密码副本或逐页导出，再更新核验状态。

## 7. 常见失败模式

| 失败模式 | 表现 | 修正 |
|---|---|---|
| 跳步 | 用户说“帮我写论文”，直接给写作模板 | 先检查视野/选题/方案是否成立，只补缺的那块 |
| 过度提问 | 一次问十几个问题 | 最多 4 个，优先问 setting、baseline、failure case、阶段 |
| 空泛建议 | “多读论文、多实验、多思考” | 换成可验收动作：读哪类、跑哪个、填哪张表 |
| 编数字 | 补一个“大约提升 5%” | 写 `[待验证]`，给验证方法 |
| 领域错配 | 把 3D 重建术语硬套到生物 | 用适配表替换名词，并标注映射理由 |
| 作业混淆 | 把 Project 节点当 P66 作业 | 回到“时间轴 + 未解问题 + PDF” |
| 只给结论 | 没有证据位置 | 补 `§/Fig./Table/file:line` 或标 `[待核对]` |

## 8. 交付前总检查

- [ ] 已判断用户处于哪一阶段，而不是泛泛回答；
- [ ] 已用课件的问题清单追问关键事实；
- [ ] 产物有字段、有判断标准、有下一步、有验收条件；
- [ ] 每个关键陈述有来源标签；
- [ ] 缺失信息标 `[待确认]`，没有用想象填满；
- [ ] 没有承诺课件明确说“不能教”的能力；
- [ ] 正式作业与过程性任务没有混写；
- [ ] 结尾有“现在就能做 / 验收标准 / 下次复盘”三段。
