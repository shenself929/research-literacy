# 论文故事与写作计划

> 用途：对应课件 P28–P46。先梳 story，再排 9 步计划；不要先写正文再想故事。

## 1. Story 五段

| 段落 | 要写什么 | 一句话草稿 |
|---|---|---|
| 任务 | 解决什么问题，输入输出是什么 | |
| 旧方法与挑战 | 以往怎么做，为什么不够 | |
| 本文贡献 | 我们做了什么，逐条编号 | |
| 技术优势/insight | 为什么这样能解决挑战，带来什么新认识 | |
| 证据 | 哪些实验/图/表支持每条贡献 | |

**检查**：

- 每条贡献是否对应一个具体挑战；
- 每个优势是否有证据，而不只是声称；
- insight 是否超出“我们提出了一个模块”。

## 6. 自评 checklist（P46）

### 技术贡献

- [ ] failure case 是否常见、重要？
- [ ] 技术是否 well-explored？
- [ ] 贡献是否足够，而不是增量调参？

### 写作清楚

- [ ] Introduction 是否讲清问题、挑战、贡献？
- [ ] pipeline figure 是否一眼看懂？
- [ ] 细节是否可复现？
- [ ] 每个模块是否有 motivation？

### 效果足够

- [ ] 相对以往提升多少？
- [ ] 是否 impressive？如果不够，故事是否诚实？

### 实验充分

- [ ] ablation 是否覆盖核心组件？
- [ ] baseline 是否合适？
- [ ] metric 是否合适？
- [ ] 是否在复杂/真实数据上验证？

### 方法合理

- [ ] setting 是否现实？
- [ ] 技术是否有明显缺陷？
- [ ] 模块是否鲁棒？
- [ ] benefit 是否被更强的 limitation 抵消？

## 7. 投稿前最后检查

- [ ] 标题、abstract、贡献三点一致；
- [ ] 每张图在正文被引用并解释；
- [ ] 所有数字能指回实验记录；
- [ ] 局限写在正文，不藏起来；
- [ ] 参考文献格式统一。
