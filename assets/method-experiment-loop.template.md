# 方法设计与实验迭代

> 用途：对应课件 P18–P19（方法设计四步）与 P21–P26（实验迭代、exploration points、SGD 类比）。

## A. 方法设计

### A1. 当前方案为什么不足

| 字段 | 内容 |
|---|---|
| 被分析的 SOTA/baseline | |
| 它的 pipeline | 输入→步骤→输出 |
| 具体不足 | 在什么数据/条件下失败，失败表现 |
| 表面原因 | 指标/现象层面 |
| 第一性原理原因 | 机制层面：为什么必然失败 |
| 证据 | 论文/实验/代码位置 |

**一句话**：

```text
现有【方法】在【条件】下失败，因为【机制原因】；这不是调参能解决的。
```

|---|---|---|---|---|---|---|

画一张 pipeline 草图（文字版）：

```text
输入 → 模块1 → 中间输出1 → 模块2 → …… → 输出
```

### A3. 三要点检查（P19）

- [ ] 不止要 work：技术创新点是什么？
- [ ] 是否在 pipeline/机制层面改动，而不是只调参？
- [ ] 产生了什么新知识、新认识或新观点？

### A4. 预期 insight

```text
如果方法有效，说明【机制假设】成立；这将改变我们对【问题】的理解。
```

## B. 实验设计

### B1. 拆 exploration points（P22）

| ID | 要验证的假设 | 对应模块/步骤 | 最小实验 | 成功判据 | 失败说明什么 | 优先级 |
|---|---|---|---|---|---|---|
| E1 | | | | | | 高 |
| E2 | | | | | | 中 |
| E3 | | | | | | 低 |

规则：

- 先做“即使失败也能排除一条路”的实验；
- 每个实验只改变一个因素；
- 从可控设定逐步加到真实设定，不要一上来跑最难 setting。

### B2. 拆 setting

| 层级 | 数据/条件 | 目的 | 进入下一层的条件 |
|---|---|---|---|
| L1 受控 | | 验证机制是否成立 | |
| L2 半真实 | | 验证鲁棒性 | |
| L3 真实 | | 验证可用性 | |

**注意**：课件的 `|| Evaluate(idea) ||` 和 `|| Experiment(idea) – Target result ||` 只是示意，没有定义范数和优化器；本表用文字记录“误差→原因→改动”，不要假装是数学上的梯度下降。

## D. 停止/转向判据

| 情况 | 动作 |
|---|---|
| 连续两轮同一假设失败 | 回到 A1 重查第一性原理原因 |
| 机制在 L1 成立但 L3 失败 | 检查 setting 差异，不要直接换方法 |
| 提升只来自调参 | 补机制层改动，否则 novelty 不足 |
| 实验成本超过预算 | 缩小 setting 或换可验证的子问题 |

## E. 交付前检查

- [ ] 每个 exploration point 都有成功/失败判据；
- [ ] 至少一个 comparison 和一个 ablation；
- [ ] 失败实验记录了“排除了什么”，不是只写“没 work”；
- [ ] 下一轮改动有明确理由，不是随机试；
- [ ] 没有编造结果数字。
