# Project 倒排计划

> 用途：对应课件 P79 的 Project 时间规划。从目标日期倒推，不按“有空就做”排。

## 1. 基本参数

| 字段 | 内容 |
|---|---|
| 目标 | 投稿会议/期刊、开题、结题、demo |
| 目标日期 | |
| 当前日期 | |
| 可用周数 | |
| 每周可投入时间 | |
| 资源约束 | 算力/样本/设备/合作者 |
| 风险偏好 | 保守 / 平衡 / Aim High |

## 2. 节点表

| 节点 | 目标日期 | 任务 | 产出物 | 验收标准 | 依赖 | 风险 |
|---|---|---|---|---|---|---|
| 启动 | | 确认 task、方向、目标 | 一页 project brief | 三句话能说清问题 | — | |

| N3 方法设计 | | 第一性原理分析、列 techniques 脑图、组合 pipeline、讨论 | 方法设计文档 + 草图 | 每个模块有原因和预期 insight | N2 | |

## 3. 倒推计算

```text
目标日期 - 当前日期 = 总周数
总周数 - 缓冲周（建议 20%）= 可用周数
每个节点分配周数 = 可用周数 × 权重
```

| 阶段 | 权重建议 | 分配周数 | 起止日期 |
|---|---|---|---|
| 视野与选题 | 10% | | |
| failure case | 15% | | |
| 方法设计 | 15% | | |
| 迭代验证 | 35% | | |
| demo/写作 | 25% | | |

权重可按领域调整，但“迭代验证”应占最大块；不要把时间全压在写作。

## 4. 周节奏

| 周期 | 要做的事 | 产出 |
|---|---|---|
| 每周一 | 定本周一个可验证假设 | 一行假设 |
| 周三 | 中期检查：数据/实验是否按计划 | 一句话状态 |
| 周五 | 记录结果与误差来源 | 迭代日志一行 |
| 每两周 | 复盘：继续/转向/缩小范围 | 决策记录 |

## 5. 风险与熔断

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 基线跑不通 | 两周内无法复现 | 换更小 setting/换 baseline |
| 方法无效 | 连续两轮同一假设失败 | 回第一性原理重查，或缩小问题 |
| 数据不足 | 样本/机时不够 | 降级为仿真/公开数据/理论分析 |
| 时间不够 | 关键节点延期 > 1 周 | 砍范围，保主线 |
| 合作阻塞 | 依赖方延迟 | 并行准备替代方案 |

## 6. 日期核对

- [ ] 所有日期都是有效日期（注意 2 月、4/6/9/11 月天数）；
- [ ] 节点之间有依赖顺序，没有倒挂；
- [ ] 留了至少 20% 缓冲；
- [ ] 目标日期与会议/期刊的实际截止日期核对过。

> 课件 P79 示例里节点 3 写作“2024 年 6 月 31 日”，这是无效日期。引用课件时必须保留原样并标 `[课件原文待确认]`，不能静默改成 6 月 30 日；做自己的计划时按真实日历填写。
